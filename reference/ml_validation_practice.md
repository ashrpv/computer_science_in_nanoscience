## 1. Сначала сформулировать обещание модели

Заполните этот паспорт **до** подбора алгоритма и открытия отложенных ответов. Решение определяется моментом его принятия: признак, полученный через неделю, нельзя использовать при выборе состава до синтеза, даже если он хорошо предсказывает итог.

| Поле | Пример для учебного кода ниже | Что указать для своих данных |
|---|---|---|
| Решение и момент | Выбрать режим синтеза до изготовления партии | Какое действие изменится из-за прогноза? |
| Единица прогноза | Одна независимо изготовленная партия | Что реально будет новым при применении? |
| Цель | Измеренный по зафиксированному протоколу размер партии, нм | Метод, время, единица и правило агрегации технических чтений |
| Доступные входы | Состав, температура и маршрут синтеза | Происхождение и момент появления каждого столбца |
| Новизна будущих данных | Партии в ещё не встречавшиеся дни (`campaign_id`) | День, поставка, прибор, химическая серия или другая группа? |
| Польза | MAE ниже константного прогноза, ошибка приемлема для решения | Допуск и цена крупных промахов, записанные заранее |

Если исходная таблица содержит три технических чтения каждой партии, это **не три независимых партии**. Для прогноза свойства новой партии обычно сохраняют исходные чтения отдельно и рассчитывают заранее определённую цель на уровне партии. Таблица для обучения содержит по одной строке на партию. Если решение касается отдельной точки спектра или пикселя, сначала заново определите единицу прогноза, целевую величину и структуру зависимостей.

## 2. Выбрать проверку по будущему применению

Разделите данные так, чтобы скрытая часть была похожа на **будущее применение**. Групповой split отвечает только на вопрос о той группе, которую вы передали алгоритму.

| Обещание | Что нельзя разнести между train и проверкой | Подходящий первый план |
|---|---|---|
| Новые измерения знакомого образца | `sample_id` | Удержать целые образцы; уточнить, есть ли практический смысл у сценария |
| Новые партии в другие дни | `campaign_id` или день | Удержать целые дни, внутри разработки проверить на других днях |
| Новая поставка сырья | `supply_id` | Удержать поставки и проверить, что день не создаёт другой общей связи |
| Следующий период при дрейфе | Время и вложенные группы | Последние полные периоды как тест; внутри разработки последовательная проверка |
| Новая химическая серия | Семейство/каркас молекул | Удержать близкие структуры вместе, если ID достоверны |

Вложенность имеет значение: один день может содержать много партий, одна партия — много проб и точек изображения. `GroupKFold(groups=campaign_id)` не разрывает связь общего сырья, если поставка появляется в нескольких кампаниях. Для задачи нового дня с календарным дрейфом случайные групповые складки внутри разработки не имитируют движение времени; используйте последовательные периоды и считайте число доступных независимых периодов. Если их слишком мало, честный результат — ограниченный пилот и план новых испытаний.

## 3. Пройти аудит утечек до `fit`

1. **Время:** доступен ли каждый вход *в момент решения*? Спектр после синтеза годится для прогноза последующей стабильности, но не для выбора условий синтеза до получения спектра.
2. **Родство:** могут ли копии, технические повторы, срезы изображения или спектры одной партии оказаться по разные стороны границы?
3. **Обучаемые преобразования:** импутация, стандартизация, PCA, отбор каналов и кодирование категорий подбираются внутри тренировочной части каждой складки. Помещайте эти шаги в `Pipeline`; заранее фиксированные физические преобразования, не оцениваемые по всему набору, описывайте отдельно.
4. **Цель:** не вычислен ли признак с использованием `y` из теста или результата измерения, который появится позднее? Идентификатор группы нужен для проверки, но обычно не служит входом модели.
5. **Процедура выбора:** одинаковы ли группы и метрика у baseline и кандидатов? Не выбираете ли алгоритм, сетку параметров, seed или порог по окончательному тесту?

Проверку пересечения групп удобно записать как исполняемый `assert`. Отсутствие пересечений не доказывает отсутствие остальных четырёх утечек: паспорт происхождения признаков остаётся необходимым.

## 4. Минимальный сквозной пример: новый день синтеза

В искусственном наборе 15 последовательных кампаний по четыре независимо синтезированные партии. `campaign_id` обозначает общий для партий сдвиг дня; `batch_id` уникален. Технические чтения уже сведены к одному целевому числу `size_nm` для каждой партии по заранее заданному протоколу. Задача: перед синтезом предсказать размер партии в **новые дни**, пользуясь лишь параметрами рецептуры: массовой долей прекурсора (%), температурой (°C) и маршрутом. Последние три кампании откладываются до окончательной проверки; по первым двенадцати выбирается конвейер. Условные диапазоны и коэффициенты генератора учебные.

```python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.dummy import DummyRegressor
from sklearn.linear_model import Ridge
from sklearn.metrics import mean_absolute_error
from sklearn.model_selection import GroupKFold, GridSearchCV, cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

rng = np.random.default_rng(314)
rows = []
for campaign in range(15):
    day_shift = rng.normal(0, 3)  # общая вариация дня, неизвестная заранее
    for batch in range(4):
        precursor_pct = 0.5 * ((campaign + batch) % 5)
        temperature_c = 80 + 10 * ((campaign + 2 * batch) % 4)
        route = ("A", "B")[(campaign + batch) % 2]
        size_nm = (52 - 3 * precursor_pct + 0.08 * (temperature_c - 90)
                   + (4 if route == "B" else 0) + day_shift
                   + rng.normal(0, 1.5))
        rows.append((f"C{campaign:02d}-B{batch}", campaign, precursor_pct,
                     temperature_c, route, size_nm))

table = pd.DataFrame(rows, columns=["batch_id", "campaign_id",
                                     "precursor_pct", "temperature_c",
                                     "route", "size_nm"])
assert len(table) == 60 and table["batch_id"].is_unique
features = ["precursor_pct", "temperature_c", "route"]
dev = table.loc[table.campaign_id < 12].copy()
test = table.loc[table.campaign_id >= 12].copy()
assert set(dev.campaign_id).isdisjoint(set(test.campaign_id))
X_dev, y_dev = dev[features], dev["size_nm"]
X_test = test[features]
groups = dev["campaign_id"].to_numpy()

# Одни и те же групповые складки для baseline и выбора alpha.
folds = list(GroupKFold(n_splits=4).split(X_dev, y_dev, groups=groups))
for fit_idx, valid_idx in folds:
    assert set(groups[fit_idx]).isdisjoint(set(groups[valid_idx]))
baseline = DummyRegressor(strategy="mean")
baseline_cv = -cross_val_score(
    baseline, X_dev, y_dev, cv=folds, scoring="neg_mean_absolute_error")

prep = ColumnTransformer([
    ("numeric", StandardScaler(), ["precursor_pct", "temperature_c"]),
    ("route", OneHotEncoder(handle_unknown="ignore"), ["route"]),
])
pipeline = Pipeline([("prep", prep), ("ridge", Ridge())])
search = GridSearchCV(
    pipeline, {"ridge__alpha": [0.1, 1.0, 10.0, 100.0]},
    scoring="neg_mean_absolute_error", cv=folds, refit=True)
search.fit(X_dev, y_dev)

# Это решение принимается до просмотра test; best_score_ — критерий
# выбора внутри разработки, не независимая оценка победителя.
use_ridge = -search.best_score_ < baseline_cv.mean()
baseline.fit(X_dev, y_dev)
chosen = search if use_ridge else baseline
print("Baseline, MAE по складкам, нм:", baseline_cv.round(2))
print("Выбран alpha:", search.best_params_["ridge__alpha"])
print("Ridge, CV MAE для выбора, нм:", round(-search.best_score_, 2))
print("Фиксируем до теста:", "Ridge" if use_ridge else "baseline")

# Единственное обращение к ответам теста происходит после выбора.
y_test = test["size_nm"]
report = test[["batch_id", "campaign_id"]].copy()
report["actual_nm"] = y_test.to_numpy()
report["baseline_nm"] = baseline.predict(X_test)
report["predicted_nm"] = chosen.predict(X_test)
report["error_nm"] = report.predicted_nm - report.actual_nm
print(report.to_string(index=False))
print("Тестовых дней / партий:", test.campaign_id.nunique(), len(test))
print("MAE baseline, нм:", mean_absolute_error(
    report.actual_nm, report.baseline_nm))
print("MAE выбранного метода, нм:", mean_absolute_error(
    report.actual_nm, report.predicted_nm))
print("MAE по дням, нм:")
print(report.groupby("campaign_id").error_nm.apply(lambda e: e.abs().mean()))
```

`folds` вычисляются **только** по 12 дням разработки и передаются обеим процедурам. В каждой складке `DummyRegressor` пересчитывает среднее, а `GridSearchCV` заново обучает `StandardScaler`, `OneHotEncoder` и `Ridge`. После выбора `search` автоматически переобучен на всей разработке (`refit=True`). `batch_id` и `campaign_id` остаются в отчёте и границах проверки, но отсутствуют в `features`.

Здесь внешняя оценка основана всего на **трёх** днях. 12 ошибок партий не равны 12 независимым доказательствам переноса на новые дни. Показанная MAE может заметно измениться на других кампаниях; она не подтверждает перенос на новые маршруты, сырьё или прибор. `OneHotEncoder(handle_unknown="ignore")` обеспечивает техническую обработку новой категории, но не проверенную точность для неё.

## 5. Прочитать результат в единицах решения

Для строки отчёта `error_nm = predicted_nm − actual_nm`: положительная ошибка означает завышение размера, отрицательная — занижение. MAE — среднее `abs(error_nm)`, здесь в нм. График факт–прогноз, ошибки по дням и список самых больших промахов дополняют одну среднюю величину. `baseline_cv` сообщает качество простого правила на складках разработки; ошибка выбранного метода на удержанных кампаниях — отдельное наблюдение. После просмотра этого теста **нельзя выбирать новый `alpha` или переставлять дни и по-прежнему называть ту же оценку независимой**.

Если дни содержат разное число партий, заранее определите, какая цель важнее: MAE по всем партиям придаёт больший вес дням с большим выпуском, средняя из MAE по дням — одинаковый вес каждому дню. Разброс ошибок складок **не является** интервалом прогноза для новой партии. При малом числе независимых дней не выдавайте узкий доверительный интервал без дополнительных предпосылок и проверки на новых днях.

Для классификации вместо регрессии предварительно определите положительный класс и цену ложного принятия/отбраковки. Порог выбирайте на разработке, если прогнозируете вероятность; `accuracy` при редком браке и `predict_proba` без проверки калибровки недостаточны. Для спектров поместите масштабирование и обучаемое снижение размерности в тот же `Pipeline` и меняйте `n_components` только внутри разработки. Для временного управления лабораторным процессом нужны последовательности состояний, действий и исходов; таблица независимых партий сама по себе не обучает политику управления.

## 6. Что сохранить вместе с моделью

Краткий отчёт, позволяющий повторить оценку, содержит: дату выгрузки и версии файлов, определение цели и протокол измерения, уровни повторов, входы и момент их появления, списки групп разработки и теста, версию Python и библиотек, baseline, сетку моделей, правило выбора, метрику и допуск, таблицу тестовых ошибок по независимым группам и область применения. Зафиксируйте ошибки измерения отдельно от ошибок прогноза новой партии. Если данные реальные, сохраните исходную выгрузку и журнал исправлений, а не только финальный notebook.

**Самопроверка:** (1) почему `train_test_split` по 60 строкам проверил бы другой вопрос; (2) что изменится в паспорте, если спектр после синтеза добавить к входам для прогноза через неделю; (3) что сделать, если один `supply_id` встречается в нескольких днях по обе стороны удержанного теста? Ответы должны ссылаться на момент решения и реальное происхождение измерений, а не только на синтаксис `GroupKFold`.
