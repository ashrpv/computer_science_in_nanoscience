# Машинное обучение: постановка задачи и проверка модели

Материал для лекции 11. Продолжение [научного и стохастического моделирования](../modeling/10-scientific_and_stochastic_modeling.md). Здесь модель обучается на данных; её качество оценивают по новым **независимым** экспериментальным единицам. Все числовые примеры ниже искусственные и не описывают конкретный материал.

## Что студент должен уметь после занятия

1. Сформулировать прогнозируемое свойство, момент прогноза, единицу наблюдения и будущий сценарий применения.
2. Составить таблицу признаков без информации, недоступной на момент прогноза.
3. Разделить партии или серии до подбора модели; удержать предобработку внутри обучающих складок.
4. Сравнить модель с простым baseline и интерпретировать ошибки в физических единицах.
5. Описать область применимости и эксперимент, который подтвердит пользу прогноза.

## 1. Научный вопрос прежде алгоритма

Пусть лаборатория измеряет размер частиц после синтеза наноэмульсии. Возможный вопрос: «Как предсказать медианный диаметр по доле масла, содержанию ПАВ, скорости перемешивания и температуре до получения следующей партии?» Цель `y` — результат заранее определённого метода измерения (например, диаметр в нм); строка `X` — одна независимо приготовленная партия, либо агрегат технических повторов этой партии. Обязательно фиксируют метод и протокол измерения, дату, прибор, единицы, пределы измерения и ID партии.

Задача **регрессии** предсказывает число (диаметр, вязкость, ёмкость сорбции). Задача **классификации** предсказывает определённую заранее категорию (например, соответствует ли заранее утверждённому диапазону стабильности). Если категория получена произвольным порогом непрерывного свойства, сохраняют также исходное число и объясняют выбор порога. Не следует учить модель на «стабильности», определённой результатом будущего теста, если этот тест недоступен на момент решения.

Признаки описывают состав, структуру и режим получения: концентрации, температуру, время, свойства сырья, дескрипторы спектра или изображения. Но морфология, измеренная после синтеза, может использоваться для прогноза позднего свойства и не может использоваться для выбора рецептуры **до синтеза**. Один и тот же столбец бывает допустимым или недопустимым в зависимости от момента прогноза.

### Контракт прогноза

| Вопрос | Пример записи |
|---|---|
| Решение | Выбрать рецептуру следующей партии |
| Объект и цель | Партия; медианный диаметр, нм |
| Доступные входы | Рецептура и настройки до синтеза |
| Горизонт | Следующая неделя, тот же метод измерения |
| Новизна | Новая партия; отдельно проверка нового сырья |
| Стоимость ошибки | Ошибка > 15 нм требует повторного синтеза |

## 2. Единица наблюдения и псевдорепликация

Если для одной партии сделано 30 изображений, число независимых синтезов равно числу партий, а не числу изображений. Даже если в таблице 300 строк, изображения одной партии обычно коррелированы. При оценке прогноза для новой партии все её изображения должны попадать в одну и ту же сторону разбиения. Альтернатива — предварительно агрегировать признаки изображений на уровне партии и иметь одну строку на партию. Агрегирование внутри всего набора до разбиения тоже может дать утечку, если используются метки или статистики других партий.

Иерархия может быть такой: поставка сырья → день синтеза → партия → образец → поле зрения → объект изображения. Группа для проверки определяется будущим применением. Если цель — новая партия при прежнем сырье, группируют по партии. Если цель — новая поставка, партии одной поставки держат вместе. Если ожидается перенос на другой прибор, нужен отдельный тест на другом приборе: `GroupKFold` по партиям сам по себе его не проверяет.

## 3. Baseline и разбиение данных

До сложной модели задают простое правило: среднее целевой величины **на обучающей части**, прогноз по известному физическому соотношению, линейная модель по одному заранее выбранному фактору или действующее лабораторное правило. `DummyRegressor` автоматически обучает константный прогноз только по обучающим данным. Выигрыш над baseline на независимом тесте служит начальной проверкой пользы, но не доказывает физическую причинность.

Тестовые партии откладывают до настройки гиперпараметров. Внутри оставшихся партий используют групповую кросс-валидацию. В каждой складке повторяют полный цикл: импутация пропусков, масштабирование, отбор признаков и обучение модели. `Pipeline` помещает обучаемую предобработку внутрь этого цикла. Предметные преобразования, чьи параметры выбраны по всем данным, также нужно перенести внутрь складки.

```text
Все партии → разбиение на разработку и финальный тест
Разработка → групповые складки → выбор метода и настроек
Разработка целиком → окончательное обучение
Финальный тест → однократный независимый отчёт
```

`GroupKFold` требует хотя бы столько различных групп, сколько складок; он не обеспечивает баланс классов. Для классификации с редким положительным исходом используют `StratifiedGroupKFold`, когда число групп и распределение классов допускают разбиение, и проверяют состав каждой складки. Если групп мало, честно показывают нестабильность оценки, а не объявляют множество технических повторов независимыми.

### Пример: регрессия с групповым тестом

Код создаёт 36 независимых учебных партий с двумя измерениями каждой. Оценка проводится по новым партиям; цель специально зависит от рецептуры и содержит случайную вариацию партии. Значения не являются экспериментальными данными.

```python
import numpy as np
from sklearn.dummy import DummyRegressor
from sklearn.impute import SimpleImputer
from sklearn.linear_model import Ridge
from sklearn.metrics import mean_absolute_error
from sklearn.model_selection import GroupKFold, GroupShuffleSplit, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(2026)
n_batches, repeats = 36, 2
batch_id = np.repeat(np.arange(n_batches), repeats)
oil = rng.uniform(5, 25, n_batches)
surfactant = rng.uniform(1, 8, n_batches)
temperature = rng.uniform(25, 55, n_batches)
X_batch = np.column_stack([oil, surfactant, temperature])
batch_effect = rng.normal(0, 3, n_batches)
y_batch = 105 + 2.2 * oil - 4.0 * surfactant + 0.6 * temperature + batch_effect
X = np.repeat(X_batch, repeats, axis=0)
y = np.repeat(y_batch, repeats) + rng.normal(0, 1.5, n_batches * repeats)

outer = GroupShuffleSplit(n_splits=1, test_size=0.25, random_state=17)
train, test = next(outer.split(X, y, groups=batch_id))
assert set(batch_id[train]).isdisjoint(batch_id[test])

baseline = DummyRegressor(strategy="mean").fit(X[train], y[train])
model = make_pipeline(SimpleImputer(strategy="median"), StandardScaler(), Ridge(alpha=1.0))
inner = GroupKFold(n_splits=4)
cv_mae = -cross_val_score(model, X[train], y[train],
                          groups=batch_id[train], cv=inner,
                          scoring="neg_mean_absolute_error")
model.fit(X[train], y[train])
print("CV MAE по складкам, нм:", np.round(cv_mae, 1))
print("Тест baseline MAE, нм:", round(mean_absolute_error(y[test], baseline.predict(X[test])), 1))
print("Тест Ridge MAE, нм:", round(mean_absolute_error(y[test], model.predict(X[test])), 1))
```

Два технических измерения одной партии оставлены для демонстрации группировки; их не стоит трактовать как удвоение размера выборки. Если обучается модель на уровне партии, агрегируют измерения цели и фиксируют правило агрегирования. Если цель — отдельное измерение, прямо записывают его уровень и корректно группируют партии. В реальном проекте seed не заменяет повторение синтеза.

## 4. Метрики и графики ошибок

Для регрессии `MAE = mean(|y−ŷ|)` выражается в единицах свойства. `RMSE = sqrt(mean((y−ŷ)²))` сильнее реагирует на крупные промахи. Выбор зависит от цены ошибки, а не от того, какая метрика даёт красивее число. `R²` может быть отрицательным на тесте и не описывает сам по себе приемлемость ошибки в нм. Сравнивают с повторяемостью измерения и с заранее определённым порогом полезности.

Помимо одного среднего числа строят `y` против `ŷ`, остаток против прогноза, ошибку по партии/диапазону концентрации/прибору и проверяют крупные промахи. Систематическая ошибка на краю диапазона может быть критичнее хорошего общего MAE. Метрики на технических измерениях коррелированы; интервал по ним как по независимым строкам будет слишком узким. Для неопределённости качества пересэмплируют независимые группы либо собирают новые партии, учитывая небольшое число групп.

## 5. Классификация и порог решения

Пусть независимым эталонным тестом для каждой партии установлено, проходит ли она критерий стабильности. Для классификации фиксируют определение положительного класса и долю положительных партий. Accuracy при дисбалансе может скрыть пропущенные нестабильные партии. Матрица ошибок показывает TP, FP, TN, FN; `recall` отвечает на вопрос о доле найденных положительных случаев, `precision` — о доле истинных среди предсказанных положительных. Указывают, какой класс несёт реальный риск.

Вероятность `predict_proba` не становится автоматически хорошо калиброванной вероятностью события. Порог выбирают на разработочных данных по стоимости ошибок; потом фиксируют и проверяют на финальном тесте. Калибровку вероятностей тоже проводят без доступа к финальному тесту. При крайне малом числе положительных партий оценка этих величин нестабильна, и дополнительный сбор данных может быть полезнее выбора ещё одного алгоритма.

## 6. Утечки и неверная область применения

| Ошибка | Последствие | Исправление |
|---|---|---|
| Поля зрения одной партии в train и test | Узнавание специфики партии | Группы или агрегация по партии |
| `StandardScaler.fit` до разбиения | Статистики теста попадают в обучение | Предобработка в `Pipeline` |
| Отбор пиков по связи со всей `y` | Тест влияет на набор признаков | Отбор в каждой складке |
| Измерение после решения как вход | Модель использует будущее | Список доступных на момент прогноза полей |
| Тест выбирает гиперпараметры | Смещённая итоговая оценка | Отдельная разработочная CV |
| Случайные партии при смене сырья | Не проверен сдвиг домена | Внешний тест по поставке/прибору |

Группировка по партии не предотвращает все утечки. Повторное использование теста для выбора рисунка, признаков или «лучшего seed» тоже делает тест частью разработки. При отсутствии независимых новых партий результат называют внутренней оценкой в заданном протоколе, а перенос на другой процесс оставляют открытым вопросом.

## 7. Мини-проект: паспорт прогностической задачи

Возьмите собственный или учебный набор по наноматериалу: условия синтеза и измеренное свойство. Представьте (1) научное решение и момент прогноза; (2) словарь признаков с единицами и временем доступности; (3) дерево вложенности и число независимых групп; (4) baseline, модель, схема CV и неприкосновенный тест; (5) MAE или матрицу ошибок в контексте лабораторного решения; (6) график ошибок по подгруппам; (7) границы применимости и план следующего независимого опыта. Если данных слишком мало для честной оценки, вместо «точной модели» предложите протокол сбора новых партий.

Возможные цели: размер капель эмульсии, остаточная масса после термообработки, площадь спектрального пика, доля покрытия поверхности, магнитная характеристика или прохождение заранее заданного порога качества. Для каждой цели проверяется момент, когда соответствующий вход реально доступен.
