# Дополнение: модули, PyPI и виртуальные окружения

Этот короткий конспект пригодится после темы [функций](02-functions.md), перед работой с [NumPy и графиками](04-numpy_and_visualization.md). Цель — понять, откуда берётся код в `import`, как установить нужную библиотеку и как сохранить вычислительную среду проекта.

## 1. От функции к модулю

**Модуль** — файл с кодом Python, который можно импортировать в другой файл. Например, вынесем расчёт из лабораторного скрипта в `calibration.py`:

```python
# calibration.py
def concentration(signal_mv, intercept_mv, slope_mv_per_mg_l):
    """Вернуть концентрацию (мг/л) по линейной калибровке."""
    if slope_mv_per_mg_l == 0:
        raise ValueError("Наклон калибровки должен быть ненулевым")
    return (signal_mv - intercept_mv) / slope_mv_per_mg_l
```

В файле `analyze.py` из той же папки:

```python
from calibration import concentration

print(concentration(signal_mv=9.5, intercept_mv=1.5, slope_mv_per_mg_l=0.8))
# 10.0 мг/л
```

`import calibration` импортирует модуль целиком; тогда вызов записывают как `calibration.concentration(...)`. Для запуска модуля через выбранный интерпретатор используют `python -m имя_модуля`: так, например, вызывают `python -m pip`. **Пакет импорта** группирует модули под общим именем, например `numpy.random`. В собственном небольшом пакете файлы обычно размещают в папке с `__init__.py`.

| Откуда берётся модуль | Пример | Что делать |
|---|---|---|
| Стандартная библиотека | `csv`, `pathlib`, `venv` | Доступна вместе с Python; отдельно через pip не устанавливается |
| Код проекта | `calibration.py` | Хранить рядом с проектом и проверять его версию вместе с анализом |
| Сторонняя библиотека | `numpy`, `matplotlib` | Устанавливать в окружение проекта |

Не называйте собственные файлы `csv.py`, `numpy.py` или `matplotlib.py`: локальный файл может перехватить импорт одноимённой библиотеки. Импорт также выполняет код верхнего уровня модуля, поэтому расчёт и запись результатов лучше размещать в функциях, вызываемых явно.

## 2. Что делают PyPI и pip

[PyPI](https://pypi.org/) — каталог публикуемых пакетов Python; **pip** — инструмент установки. Имя устанавливаемого дистрибутива и имя в `import` иногда различаются. Например, устанавливают `scikit-image`, а импортируют `skimage`. Проверяйте имя установки в документации библиотеки.

```bash
python -m pip install numpy
python -m pip show numpy
```

Форма `python -m pip` связывает установку с тем интерпретатором, которым затем запускается анализ. `pip` может поставить зависимости автоматически. При установке нового пакета проверяйте его название и источник: похожее написание может означать другой проект.

## 3. Окружение для одного научного проекта

**Виртуальное окружение** (`venv`) содержит отдельный интерпретатор и набор установленных библиотек. Создайте его из корня репозитория с Python 3.11 или 3.12:

```bash
python -m venv .venv
```

На Linux/macOS активируйте его командой `source .venv/bin/activate`, в Windows PowerShell — `.venv\Scripts\Activate.ps1`. Если системная команда для нужного Python называется `python3` или `py -3.12`, подставьте её при создании окружения. После активации:

```bash
python -m pip install -r requirements.txt
python -c "import sys, numpy; print(sys.executable, numpy.__version__)"
```

Команды выполняются из корня этого репозитория: его `requirements.txt` перечисляет версии для примеров курса. Для отдельного исследовательского проекта ведите собственный список зависимостей и фиксируйте версию Python. Саму папку `.venv` в Git не добавляют: на другом компьютере окружение создают заново из списка зависимостей. Команда `deactivate` завершает активацию; окружение от этого не удаляется.

Если активировать окружение неудобно, можно указать его интерпретатор явно: `.venv/bin/python -m pip ...` на Linux/macOS или `.venv\Scripts\python.exe -m pip ...` в Windows. В notebook проверьте `sys.executable`: установка пакета в терминале не меняет автоматически выбранное ядро notebook.

## Небольшая проверка

Создайте `calibration.py` и `analyze.py` из примера. Запустите `analyze.py`, затем создайте окружение, установите зависимости курса и выясните, из какого файла импортируется NumPy:

```python
import numpy as np
print(np.__file__)
```

Путь должен указывать на установленную библиотеку в выбранном окружении, а не на ваш случайно названный `numpy.py`.
