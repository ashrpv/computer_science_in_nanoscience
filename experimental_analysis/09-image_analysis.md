## 1. Масштабная калибровка и съёмка

Если масштабная линейка длиной `L` занимает `N` пикселей, размер пикселя `s = L/N`. Для изотропного изображения:

$$L_{phys}=L_{px}s,\qquad A_{phys}=A_{px}s^2,\qquad P_{phys}=P_{px}s.$$

При малой относительной неопределённости масштаба 2% её вклад составляет примерно 2% в длину, 4% в площадь и 6% в объём. Это вклад калибровки, не полная неопределённость сегментации. Для разных шагов по осям используют отдельные `s_x`, `s_y`; для 3D дополнительно `s_z`.

После изменения размера изображения масштаб меняется. Его фиксируют для каждого режима камеры и увеличения. При съёмке контролируют фокус, экспозицию, насыщение, освещение, геометрию и битность. Масштабную линейку и подписи исключают из области анализа по заданному правилу.

**Пример с единицами.** Если надпись `500 нм` соответствует линейке длиной `125 px`, то `s=4 нм/px`. Силуэт с площадью `314 px²` имеет площадь `314·4²=5024 нм²` и эквивалентный диаметр `√(4·5024/π)≈80 нм`. Это диаметр *равновеликого круга*, а не измеренный диаметр описанной окружности или размер кристаллита. При цене пикселя `4 нм` ошибка до одного пикселя на каждом конце линейки (`N=125±2 px`) даёт *предельное изменение* масштаба около `1,6%`, ещё до неопределённости длины, обозначенной на линейке, и ошибки выделения контура. Нельзя переносить `4 нм/px` на соседний JPEG без документированной идентичности режима съёмки.

В [пяти учебных микрофотографиях](data/microscopy_examples/README.md) физическая линейка есть у `P02`, `N01`, `N02` и `N03`; у `P01` её нет. Для `N02` надпись `0,5 мкм` соответствует `500 нм`. Реальную длину линейки **в пикселях нужно измерить** на полном исходном изображении: число `125 px` выше только учебное. Если уменьшить ширину и высоту изображения вдвое, новая цена пикселя для той же сцены станет `2s`, а при кадрировании без изменения размера она сохранится. Метаданные о вероятном способе съёмки не заменяют экспериментальную калибровку.

## 2. Выборка: образцы, поля зрения и объекты

Иерархия обычно выглядит так: независимый образец → поля зрения → объекты. Координаты полей выбирают случайно или систематически по заранее заданной схеме. Тысячи частиц в одном кадре не заменяют несколько независимых образцов.

Поле зрения — единица отбора внутри образца, но не обязательно независимая единица для сравнения воздействий. Вывод о технологии опирается на уровень назначения воздействия: образец, партию или иной объект дизайна. Указывают отдельно число образцов, полей и объектов.

**Два разных вопроса при неравном числе частиц.** Если два поля содержат `10` и `100` принятых частиц, средние размеры `50` и `20 нм`, среднее по всем частицам равно `(10·50+100·20)/110≈22,7 нм`; среднее двух средних по полям — `35 нм`. Первое взвешивает поле числом зарегистрированных объектов, второе даёт полям равный вес. Оба числа зависят от правила выбора полей и обнаружения частиц. При сравнении синтезов сначала получают одну согласованно определённую характеристику на независимый образец, а затем сравнивают образцы.

## 3. Предобработка, порог и морфология

Выбор канала, коррекция фона и подавление шума должны сохранять интересующие объекты. Сильная коррекция фона может стереть крупные частицы или поры.

Otsu выбирает глобальный порог по гистограмме. При неравномерном освещении нужен локальный порог, коррекция фона или другая модель. Знак сравнения зависит от полярности: светлые объекты — `image > threshold`, тёмные — `image < threshold`.

Сохраните вход каждого шага для проверки: исходный кадр → область интереса (ROI) → выбор канала и контраст → бинарная маска → разделённые метки → таблица. Указывайте положение ROI в координатах **исходного кадра**; `image[80:1350, 150:1900]` берёт строки `80…1349` и столбцы `150…1899`. Масштаб, измеренный на исходнике, сохраняется для такого кропа. Порог и фильтр, удачные на одном кадре, проверяют на другом ROI без повторного подбора на нём.

| Операция | Что меняет | Возможное искажение |
|---|---|---|
| Удаление мелких компонент | Отбрасывает области ниже заданной площади | Теряет реальные мелкие частицы |
| Заполнение отверстий | Убирает малые отверстия внутри объекта | Уменьшает измеряемую пористость |
| Opening | Убирает тонкие выступы и перемычки | Меняет контур |
| Closing | Соединяет близкие разрывы | Объединяет объекты |

Размеры операций переводят из физических единиц в пиксели. Выбор связности 4 или 8 в 2D влияет на соединение диагональных пикселей. Карта границ показывает переходы яркости, но для площади нужна заполненная маска объекта.

## 4. Маска и watershed: пример

Пример использует API scikit-image 0.25.2 из файла зависимостей. `min_area_um2` — минимальная площадь объекта, `marker_distance_um` — расстояние между маркерами.

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from scipy import ndimage as ndi
from skimage import filters, morphology, measure, feature, segmentation, draw

rng = np.random.default_rng(42)
image = np.zeros((160, 200), dtype=float)
for center, radius in [((50, 55), 19), ((50, 85), 19), ((112, 142), 16)]:
    rr, cc = draw.disk(center, radius, shape=image.shape)
    image[rr, cc] = 1.0
image = np.clip(ndi.gaussian_filter(image, 1) + rng.normal(0, 0.02, image.shape), 0, 1)
s = 0.2  # мкм/px для учебного изображения
params = {"min_area_um2": 1.0, "hole_area_um2": 0.5,
          "marker_distance_um": 2.0, "threshold_offset": 0.0}

def segment(image, s, params):
    if image.ndim != 2 or not np.isfinite(image).all() or s <= 0:
        raise ValueError("Нужно конечное 2D-изображение и положительный масштаб")
    if image.max() == image.min():
        raise ValueError("Изображение не содержит контраста")
    threshold = filters.threshold_otsu(image) + params["threshold_offset"]
    mask = image > threshold
    min_px = max(1, int(np.ceil(params["min_area_um2"] / s**2)))
    hole_px = max(1, int(np.ceil(params["hole_area_um2"] / s**2)))
    mask = morphology.remove_small_objects(mask, min_size=min_px, connectivity=2)
    mask = morphology.remove_small_holes(mask, area_threshold=hole_px, connectivity=2)
    distance = ndi.distance_transform_edt(mask)
    coords = feature.peak_local_max(
        distance, labels=mask, exclude_border=False,
        min_distance=max(1, int(np.ceil(params["marker_distance_um"] / s))),
    )
    if len(coords) == 0:
        raise ValueError("Не найдены маркеры объектов")
    markers = np.zeros(mask.shape, dtype=int)
    markers[tuple(coords.T)] = np.arange(1, len(coords) + 1)
    labels_all = segmentation.watershed(
        -distance, markers, mask=mask, connectivity=np.ones((3, 3), dtype=bool)
    )
    # Явное учебное правило: исключаем объекты, касающиеся границы кадра.
    labels = segmentation.clear_border(labels_all)
    labels = morphology.remove_small_objects(labels, min_size=min_px)
    return mask, labels, threshold

mask, labels, threshold = segment(image, s, params)
fig, axs = plt.subplots(1, 3, figsize=(10, 3), layout="constrained")
for ax, values, title in zip(axs, [image, mask, labels], ["Исходное", "Маска", "Объекты"]):
    ax.imshow(values, cmap="gray" if title != "Объекты" else "tab20")
    ax.set(title=title)
    ax.set_axis_off()
plt.show()
```

Watershed разделяет маску по маркерам на рельефе отрицательного расстояния. Избыток маркеров дробит частицу, недостаток объединяет соседние. Метод не восстанавливает достоверно скрытый контур при сильном перекрытии в проекции. Маркеры и маски проверяют на ручной разметке.

Исключение объектов у края может смещать распределение против крупных объектов. Для количественной работы заранее выбирают подходящее правило рамки отбора и оценивают его влияние. В примере полная маска сохраняется отдельно от меток принятых объектов.

## 5. Таблица измерений

```python
properties = measure.regionprops_table(
    labels, spacing=(s, s),
    properties=("label", "area", "perimeter", "equivalent_diameter_area",
                "axis_major_length", "axis_minor_length", "eccentricity", "solidity"),
)
objects = pd.DataFrame(properties).assign(sample_id="S001", field_id="F001")
objects["circularity"] = 4 * np.pi * objects["area"] / objects["perimeter"]**2
objects["aspect_ratio"] = objects["axis_major_length"] / objects["axis_minor_length"]
print(objects[["label", "area", "equivalent_diameter_area", "circularity"]])
```

`spacing` уже переводит геометрические величины в физические единицы: повторно умножать площадь на `s²` не нужно. Пример периметра рассчитан на одинаковый масштаб по двум осям. Для анизотропных пикселей проверяют поддержку конкретного свойства.

Числа в коде имеют физический смысл: при `s=0,2 мкм/px` площадь `1 мкм²` соответствует `25 px²`, а минимальное расстояние `2 мкм` между маркерами — `10 px`. Выбор `min_area_um2` после просмотра результата с целью удалить «неудобные» мелкие частицы сдвинет распределение. Даже если средний эквивалентный диаметр верен на искусственных дисках, на снимке с огранёнными или перекрытыми частицами оценка может оказаться неверной.

| Признак | Определение | Ограничение |
|---|---|---|
| Эквивалентный диаметр | $d_{eq}=\sqrt{4A/\pi}$ | Диаметр равновеликого круга, не 3D-размер |
| Circularity | $4\pi A/P^2$ | Сильно зависит от оценки периметра |
| Aspect ratio | `major / minor` | Оси эквивалентного эллипса |
| Eccentricity | Эксцентриситет | Безразмерная характеристика формы |
| Solidity | Площадь / площадь выпуклой оболочки | Чувствительность к вогнутостям |

Пикселизация и метод оценки периметра влияют на круглоту; значения могут отличаться от идеальной геометрии. Сравнивать серии следует при сопоставимых разрешении и правилах обработки. Для вырожденных объектов проверяют нулевые периметр и малую ось.

Размеры описывают распределением: медианой, квантилями, числом объектов и правилом отсечения. Среднее по всем частицам может скрывать различия между полями и образцами.

### Цвет на микрофотографии пигмента

Для цветного JPEG сначала определяют маски **внутренних областей частиц**: светлый фон, ореолы у границы, блики, перекрытия и затемнение не должны незаметно попадать в статистику цвета. Если файл маркирован как sRGB, `skimage.color.rgb2lab(rgb)` позволяет представить **закодированные цвета изображения** в координатах `L*`, `a*`, `b*`; приводят распределения по нескольким областям и число пикселей, а не один «цвет образца». Изменение освещения и баланса белого, толщина прозрачной частицы и режим микроскопии влияют на эти значения. Встроенный профиль sRGB не заменяет измерение цвета материала при заданном источнике света, геометрии наблюдения и калибровке прибора. Спектр отражения связывают с фотографией только при документированной идентичности образца и условий.

Пример чтения **одной вручную выбранной внутренней площадки** на `P01` (координаты на исходном JPEG; участок нужно проверить визуально перед использованием):

```python
from skimage import io, color

p01 = io.imread("experimental_analysis/data/microscopy_examples/raw/1a.JPG")
assert p01.shape[:2] == (1536, 2048)
rgb = p01.astype(float) / 255.0  # для данного 8-битного JPEG
selected = np.zeros(p01.shape[:2], dtype=bool)
selected[490:510, 1050:1080] = True  # пример внутреннего участка, 20 × 30 px
lab = color.rgb2lab(rgb)
print("n_pixels:", selected.sum())
print("median L*, a*, b*:", np.median(lab[selected], axis=0))
print("Q25–Q75:", np.quantile(lab[selected], [0.25, 0.75], axis=0))
```

Повторите на нескольких **отдельно размеченных внутренних участках** и сохраните их координаты или маски. Сравните типичные значения между областями, а также выбранный участок до и после обоснованной коррекции освещения. Несколько сотен пикселей одной пластинки не являются сотнями независимых синтезов; `P01` не имеет масштабной линейки, и вычислять микрометры по нему нельзя. Светлый фон на JPEG не обязан быть белым цветовым эталоном. Для `P02` сильное затемнение и цветовые ореолы ещё существеннее меняют результат; один глобальный порог насыщенности не должен автоматически заменить ручное QC.

На СЭМ-снимке перед сегментацией может понадобиться растяжение или локальная коррекция контраста. Сравнивают исходный и исправленный варианты на **одном ROI** с одинаковым ручным контролем, а границы маски всегда накладывают на исходный кадр. Локальная коррекция может усилить шум и изменить найденные размеры; её качество нельзя оценить по визуальной выразительности картинки.

**Мост к настоящему JPEG.** В синтетическом примере выше объекты светлые; в [реальном поле `N03`](data/microscopy_examples/README.md) округлые силуэты тёмные. Следующий код читает файл и строит лишь *начальную маску* на ROI без линейки; численные размеры намеренно не считает, поскольку студент ещё не измерил число пикселей линейки `500 нм` и не проверил контуры:

```python
from skimage import io, color

raw = io.imread(
    "experimental_analysis/data/microscopy_examples/raw/2019-12-13-9-2.jpg"
)
assert raw.shape[:2] == (1705, 2048)
roi = raw[80:1350, 150:1900]
gray = color.rgb2gray(roi)
soft = filters.gaussian(gray, sigma=1.0)
first_mask = soft < filters.threshold_otsu(soft)  # тёмные объекты
boundaries = segmentation.find_boundaries(first_mask)
overlay = np.repeat(gray[..., None], 3, axis=2)
overlay[boundaries] = (1, 0, 0)
fig, axs = plt.subplots(1, 2, figsize=(9, 4), layout="constrained")
axs[0].imshow(roi)
axs[1].imshow(overlay)
for ax in axs:
    ax.set_axis_off()
plt.show()
```

Оцените маску на исходных пикселях, помечая пропуски, ложные частицы, касания и оставшиеся подписи. При необходимости примените шаги очистки и `watershed` из искусственного примера **с инверсией полярности**, а параметры в пикселях переведите из уже измеренного масштаба. Для `N02` задача иная: сначала сравнивают исходник, умеренное растяжение контраста и локальную коррекцию на независимом контрольном ROI. Для `N01` плотное наложение оставляет невидимые контуры; автоматическое «разделение» не создаёт недостающую информацию.

## 6. Пористость и дефектность

Площадная доля пор $\phi_A=A_{pore}/A_{ROI}$. Нужно явно определить поры и область интереса; подписи, артефакты и края исключают согласованно. Маска из примера выделяет светлые частицы, поэтому её долю нельзя без переопределения назвать пористостью.

Переход от 2D-доли к объёмной требует обоснованного стереологического отбора и репрезентативных сечений. Из одного изображения поверхности нельзя автоматически получить объёмную пористость или различить открытые и закрытые поры.

Для дефектности можно считать число дефектов на площадь, долю их площади, распределение размеров и расстояния. Класс дефекта задают до анализа и проверяют вручную.

## 7. Устойчивость и иерархическая неопределённость

Варьируют допустимые порог, минимальную площадь, расстояние маркеров и правила края. Ищут диапазон, в котором сохраняются научные выводы, а не параметр с удобным результатом.

```python
rows = []
for offset in [-0.03, 0.0, 0.03]:
    for min_area in [0.5, 1.0, 2.0]:
        changed = {**params, "threshold_offset": offset, "min_area_um2": min_area}
        _, current, _ = segment(image, s, changed)
        table = pd.DataFrame(measure.regionprops_table(
            current, spacing=(s, s), properties=("label", "equivalent_diameter_area")
        ))
        rows.append({"offset": offset, "min_area_um2": min_area,
                     "n_objects": len(table),
                     "median_diameter_um": table["equivalent_diameter_area"].median()})
print(pd.DataFrame(rows))
```

Повторный запуск на том же изображении оценивает алгоритмическую часть, не вариацию материала. Для обобщения учитывают структуру $y_{ijk}=\mu+sample_i+FOV_{j(i)}+\varepsilon_{ijk}$. В иерархическом bootstrap сначала выбирают независимые образцы, затем поля внутри них; число пикселей не является размером независимой выборки.

**Как проверить маску до расчёта распределения.** На заранее отложенном контрольном ROI вручную обозначьте хорошо различимые объекты и отдельно пометьте касания с неизвестным контуром. Для бинарных масок `IoU = |M_auto ∩ M_manual| / |M_auto ∪ M_manual|`. Если алгоритм выделил `80 px`, человек `100 px`, совпало `70 px`, то объединение составляет `80+100−70=110 px`, а `IoU≈0,64`. Одновременно посчитайте пропущенные, ложные и ошибочно разделённые *объекты*: высокий IoU всей площади не гарантирует правильного числа частиц. Если порог подбирали на этих же ручных контурах, измеренная точность не является независимой проверкой; используйте другой ROI. Пиксели внутри поля коррелируют, поэтому `n=100` ручных пикселей — не `100` независимых образцов.

**Разбор иерархии на опубликованной таблице ПЭМ.** В отличие от `N01–N03`, [таблица магнетита](data/tem_magnetite/README.md) содержит *готовые* размеры силуэтов без связанных с ними первичных снимков. Для `V12` можно напрямую сравнить два веса полей:

```python
from pathlib import Path

table = pd.read_csv(
    Path("experimental_analysis/data/tem_magnetite/measurements.csv"),
    dtype={"sample_id": "string", "image_id": "string"},
)
v12 = table.loc[table["sample_id"] == "V12"]
by_image = v12.groupby("image_id", as_index=False).agg(
    n_particles=("size_nm", "size"),
    mean_size_nm=("size_nm", "mean"),
    median_size_nm=("size_nm", "median"),
)
print(by_image)
print("По всем частицам:", v12["size_nm"].mean())
print("Среднее трёх снимков:", by_image["mean_size_nm"].mean())
```

В трёх снимках `54/190/245` записанных размеров; средние по снимкам около `48,84/42,02/28,63 нм`. Поэтому оценки `36,06` и `39,83 нм` различаются **только из-за веса полей**, даже без изменения исходных записей. Здесь `size_nm` — смешанная по неразмеченной форме величина: для округлых силуэтов использовали диаметр описанной окружности, для кубических — сторону квадрата. Нельзя переименовывать результат в эквивалентный диаметр из `regionprops`, определять форму по порогу `25 нм` или считать эту таблицу результатом обработки пяти JPEG. Нет условий съёмки и плана выбора полей, поэтому оба средних характеризуют зарегистрированные данные, а не автоматически весь синтезированный материал.

## 8. Пакетная обработка и мини-проект

Для каждого поля сохраняют исходное изображение, масштаб, полную маску, метки объектов, таблицу свойств и QC. Метки одного поля уникальны только вместе с `sample_id` и `field_id`. В таблице полей отдельно фиксируют даже кадры с нулём объектов и неуспешные обработки; иначе они исчезнут из статистики серии.

Цикл по файлам выполняет одну и ту же функцию `segment`, получает масштаб и ID из реестра и записывает параметры с версией кода. Сводный QC включает насыщение, долю объектов у края, число маркеров и примеры наложения контуров на исходник.

Мини-проект: сравнить несколько полей независимых образцов, обосновать калибровку и выбор координат, получить распределения размеров и карту устойчивости параметров. Отдельно указать число образцов, полей, принятых и исключённых объектов, а также причину исключения.

Для самостоятельной практики с **готовой таблицей измерений**, а не с пикселями, используйте [мини-проект по ПЭМ магнетита](09-tem-homework.md). Его 20 отдельно синтезированных образцов позволяют изучить распределения внутри и между снимками и вариацию между синтезами. Отсутствие исходных микрофотографий и меток режимов синтеза ограничивает проверку сегментации и причинные сравнения; форма каждой частицы не известна.

Для практики на **реальных пикселях** используйте [пять микрофотографий](09-microscopy-homework.md): две цветные микрофотографии пигментных частиц, плотное поле огранённых частиц, СЭМ-снимок, требующий проверки коррекции контраста, и поле округлых частиц для автоматической сегментации. Набор содержит примеры разных задач, а не повторные поля известных образцов; он не связан идентификаторами с таблицей магнетита. В задании по цвету sRGB-пиксели фотографии анализируются отдельно от цвета материала при стандартизованном освещении.
