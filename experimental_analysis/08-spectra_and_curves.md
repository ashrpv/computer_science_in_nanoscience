## 1. Калибровка и входные данные

Обработка включает калибровку, предобработку, извлечение признаков, контроль качества и оценку неопределённости. Каждая стадия влияет на результат измерения.

Калибровка оси `x` связывает отсчёты прибора с длиной волны, частотой, временем или деформацией. Калибровка `y` задаёт ноль, чувствительность и рабочий диапазон через темновой сигнал, холостой опыт и стандарт. Проверяют монотонность координаты, единицы, дубликаты, пропуски и насыщение.

Вместе с `x` и `y` сохраняют ID образца и партии, повтор, режим прибора, геометрию, экспозицию, дату и версию калибровки. Имя файла не заменяет эти поля.

**Начните с измеряемой величины, а не с метода фильтрации.** Одна и та же форма массива `(x, y)` может означать принципиально разные наблюдения:

| Данные | Ось и сигнал | Контроль до извлечения признаков | Допустимый итог |
|---|---|---|---|
| Фотолюминесценция | длина волны, нм; интенсивность, отн. ед. | тёмный сигнал, пустая подложка, насыщение | положение и площадь полосы в заданных условиях |
| Отражение | длина волны, нм; сигнал образца и белого эталона | тёмный сигнал, спектральная чувствительность, уровень эталона | относительный спектр отражения, если измерена калибровка |
| Дифракция | `2θ`, градусы; интенсивность в единицах выгрузки | фактическая сетка, подложка/матричный контроль, стандарт прибора | ширина/положение *наблюдаемой* особенности, фазовая гипотеза |
| Реология | скорость сдвига, с⁻¹; напряжение, Па | температура, порядок прямого и обратного ходов, диапазон скоростей | кажущаяся вязкость и параметры модели на указанном интервале |

Например, при одном значении длины волны сигнал образца `S=720`, темновой `D=20` и белый `W=1020` дают `(S-D)/(W-D)=0,70` **относительно выбранного белого**. В общем случае, если известно отражение эталона `R_white(λ)`, вычисляют `R_sample(λ)=[S(λ)-D(λ)]/[W(λ)-D(λ)]·R_white(λ)`. Деление делают по соответствующим длинам волн и проверяют ненулевой знаменатель, диапазон линейности и сопоставимость геометрии/экспозиции. Числа вне интервала 0–1 помечают для проверки, а не молча обрезают. Один CSV с названием `white` без подтверждённых тёмного сигнала, эталона и условий не позволяет объявить данные абсолютным коэффициентом отражения или точно восстановить цвет пигмента.

## 2. Фон и сглаживание

Фон описывает медленную составляющую сигнала. Полином подходит при простой форме и надёжных опорных участках; AsLS и родственные методы удобны для более сложного фона. Слишком гибкий фон может вычесть широкую полезную полосу. Оценку фона сохраняют отдельно от исправленного сигнала. Если есть измеренный холостой образец, сначала проверяют его соответствие режиму и изменчивость; математическая оценка фона по самому спектру отвечает на другой вопрос. Вычитание двух шумных измерений добавляет шум обоих источников.

Сглаживание снижает шум, но может сместить максимум, изменить ширину и площадь, создать ложные экстремумы. Окно выбирают относительно физической ширины признака. Для Savitzky–Golay `polyorder < window_length`; обычная интерпретация окна и производных предполагает равномерную сетку. На неравномерной сетке нужен подходящий метод или обоснованная интерполяция.

Небольшие отрицательные значения после вычитания фона возможны из-за шума. Существенное систематическое пересечение полезного сигнала оценкой фона требует проверки; правило «всё отрицательное удалить» искажает площадь.

**Как выбрать окно и фон до результата.** На нескольких представительных исходных кривых отметьте вручную области без ожидаемых полос и узкую интересующую полосу. Укажите максимальную допустимую ширину окна сглаживания в физических единицах и переведите её в отсчёты: при шаге 0,5 нм окно из 11 точек охватывает примерно `(11-1)·0,5=5` нм. Это короче учебного гауссовского пика с `σ=8` нм и шириной около 19 нм. Сравните исходник, оценку фона, исправленный сигнал и остатки обработки *на одном графике*, затем применяйте одинаковое правило ко всей серии. Если широкая полоса исчезает вместе с фоном или узкая сливается с соседней, параметр не подходит для этой задачи.

## 3. Воспроизводимый пример обработки спектра

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from pybaselines import Baseline
from scipy.signal import savgol_filter, find_peaks, peak_widths
from scipy.integrate import trapezoid

rng = np.random.default_rng(42)
x = np.linspace(400, 800, 801)  # нм, равномерный шаг 0.5 нм
intensity = (0.1 + 0.0003 * (x - 400)
             + np.exp(-0.5 * ((x - 520) / 8)**2)
             + 0.6 * np.exp(-0.5 * ((x - 650) / 14)**2)
             + rng.normal(0, 0.01, x.size))
spectrum = pd.DataFrame({"x": x, "intensity": intensity})
params = {"lam": 1e6, "p": 0.01, "window": 11, "polyorder": 3,
          "prominence": 0.08, "distance": 30}

def process_curve(frame, settings=params):
    if not {"x", "intensity"}.issubset(frame.columns):
        raise ValueError("Нужны столбцы x и intensity")
    x = frame["x"].to_numpy(dtype=float)
    y = frame["intensity"].to_numpy(dtype=float)
    if len(x) < settings["window"] or not np.isfinite([x, y]).all():
        raise ValueError("Короткая кривая или неконечные значения")
    dx = np.diff(x)
    if not (dx > 0).all():
        raise ValueError("x должен строго возрастать, без дубликатов")
    if not np.allclose(dx, dx[0], rtol=1e-5, atol=1e-10):
        raise ValueError("Этот пример рассчитан на равномерную сетку")
    baseline, _ = Baseline(x_data=x).asls(
        y, lam=settings["lam"], p=settings["p"]
    )
    corrected = y - baseline
    smooth = savgol_filter(corrected, settings["window"], settings["polyorder"])
    peaks, properties = find_peaks(
        smooth, prominence=settings["prominence"], distance=settings["distance"]
    )
    widths, levels, left, right = peak_widths(smooth, peaks, rel_height=0.5)
    positions = np.arange(len(x))
    left_x = np.interp(left, positions, x)
    right_x = np.interp(right, positions, x)
    features = pd.DataFrame({
        "peak_x_nm": x[peaks], "height": smooth[peaks],
        "prominence": properties["prominences"],
        "width_half_prominence_nm": right_x - left_x,
    })
    band = (x >= 480) & (x <= 560)
    if band.sum() < 2 or x.min() > 480 or x.max() < 560:
        raise ValueError("Кривая не покрывает полосу 480–560 нм")
    area = trapezoid(corrected[band], x=x[band])
    processed = frame.assign(baseline=baseline, corrected=corrected, smooth=smooth)
    return processed, features, float(area)

processed, features, area = process_curve(spectrum)
print(features)
print("Площадь 480–560 нм:", area)
fig, ax = plt.subplots(figsize=(8, 4), layout="constrained")
ax.plot(x, intensity, label="Исходный сигнал")
ax.plot(x, processed["baseline"], label="Оценка фона")
ax.plot(x, processed["smooth"], label="После обработки")
ax.set(xlabel="Длина волны, нм", ylabel="Интенсивность, отн. ед.")
ax.legend()
plt.show()
```

Для реальных данных параметры предварительно проверяют на стандартах и размеченной подвыборке. `distance` задаётся в отсчётах, а не в нанометрах. Пропуски нельзя просто удалить, если это создаёт разрыв сетки: нужно отдельное решение о восстановлении или разделении диапазона. Насыщение проверяют по пределам конкретного прибора.

**Проверка результата на известной искусственной форме.** Без шума и второго пика максимум первой гауссовой компоненты должен находиться в `520 нм`; её `σ=8 нм`, а теоретическая FWHM `≈18,84 нм`. Полный интеграл компоненты от минус бесконечности до плюс бесконечности равен `8√(2π)≈20,05` отн. ед.·нм; площадь на `480–560 нм` практически совпадает с ним. Это проверка порядка величин, а не целевое равенство: второй пик даёт небольшой хвост в этом интервале, шум и оценённый фон изменяют результат. Если функция выдаёт, например, ширину `37` **отсчётов**, её нельзя подписать `37 нм`: при шаге 0,5 нм это примерно `18,5 нм`. Даже после перевода `width_half_prominence_nm` нельзя автоматически назвать FWHM, поскольку определение уровня для `peak_widths` иное.

**Проверка настройки без переписывания сырых данных.** После первого запуска можно сравнить разрешённые варианты окна, используя один и тот же вход:

```python
comparison = []
for window in (7, 11, 21):
    local = {**params, "window": window}
    current, found, band_area = process_curve(spectrum, local)
    in_band = found.loc[found["peak_x_nm"].between(500, 540)]
    comparison.append({
        "window": window,
        "n_peaks_total": len(found),
        "peak_500_540_nm": in_band["peak_x_nm"].iloc[0] if len(in_band) else np.nan,
        "area_480_560": band_area,
    })
print(pd.DataFrame(comparison))
```

Площадь здесь рассчитана *до сглаживания*, поэтому изменение только окна обязано оставить `area_480_560` неизменной. Если она меняется, ищите незаметную подмену сигнала или границ интегрирования. При изменении метода фона площадь уже должна изменяться, и это отдельная ось проверки чувствительности. Число найденных максимумов и положение могут меняться от окна; пропущенную полосу регистрируют как `NaN`, а не подставляют близкий пик без просмотра.

## 4. Положение, ширина и площадь

`height` ограничивает абсолютную высоту, `prominence` характеризует выделение пика относительно окружающего сигнала, `distance` подавляет близкие срабатывания, `width` помогает отсекать слишком узкие пики.

FWHM — ширина на половине высоты над базовой линией. Для гауссовского пика $FWHM=2\sqrt{2\ln2}\,\sigma\approx2.355\sigma$. Однако `peak_widths(..., rel_height=0.5)` измеряет ширину на половине **prominence**. Она совпадает с FWHM лишь при подходящем фоне и изоляции пика; поэтому в коде столбец назван `width_half_prominence_nm`.

`left` и `right` — дробные индексы пересечений. Их переводят в физическую координату интерполяцией; умножение на шаг подходит лишь для равномерной сетки.

Площадь вычисляют после коррекции фона, на согласованных границах:

$$A\approx\sum_i\frac{y_i+y_{i+1}}2(x_{i+1}-x_i).$$

Единица площади — произведение единиц осей. Интегрирование идёт в переданном порядке, поэтому координата должна быть проверена. В примере площадь берётся по несглаженному исправленному сигналу, чтобы отделить влияние сглаживания на детектор от влияния на интеграл.

## 5. Модель формы и перекрывающиеся пики

| Форма | Особенность | Что оценивать |
|---|---|---|
| Gaussian | Быстро затухающие хвосты | Центр, амплитуда, σ |
| Lorentzian | Более длинные хвосты | Центр, амплитуда, полуширина γ |
| Voigt | Свёртка Gaussian и Lorentzian | Центр, ширины и площадь |
| Асимметричная модель | Разные стороны пика | Дополнительную асимметрию с физическим обоснованием |

Перекрывающиеся пики оценивают совместно. Проверяют ограничения центров и ширин, положительность амплитуд, разрешение прибора и обоснованность числа компонент. Коррелирующие параметры могут дать широкие интервалы даже при хорошем совпадении суммарной кривой. Остатки и устойчивость важнее одного R².

### Разбор настоящей приборной пары: дифрактограмма и матричный контроль

В [наборе Fe–SiO₂](../datasets/xrd_fe_silica/README.md) выгрузки `3911` (с железом) и `3912` (контроль без железа) получены от **разных физических образцов** при одинаковых указанных размере матрицы и прокаливании. Оба файла содержат две числовые колонки без заголовка. Загрузим их без изменения и начнём с проверки оси:

```python
from pathlib import Path

root = Path("datasets/xrd_fe_silica/raw")  # запуск из корня репозитория
curves = {}
for sample_id in ("3911", "3912"):
    data = np.loadtxt(root / f"IGIC_nps_{sample_id}.xy")
    assert data.ndim == 2 and data.shape[1] == 2
    assert np.isfinite(data).all() and np.all(np.diff(data[:, 0]) > 0)
    curves[sample_id] = data

x_fe, y_fe = curves["3911"].T
x_si, y_si = curves["3912"].T
assert np.allclose(x_fe, x_si, rtol=0, atol=1e-5)
print(len(x_fe), x_fe[[0, -1]], np.diff(x_fe).min(), np.diff(x_fe).max())
fig, ax = plt.subplots(layout="constrained")
ax.plot(x_fe, y_fe, label="3911: Fe–SiO₂")
ax.plot(x_si, y_si, label="3912: SiO₂")
ax.set(xlabel="2θ, °", ylabel="Интенсивность, ед. выгрузки")
ax.legend()
plt.show()
```

Получатся **1888 отсчётов** в каждом файле, фактическая ось примерно от `5,00000` до `80,28934°` с шагом около `0,03990°`: заявленные в подписи 5–80° и 0,04° — номинальная программа, а не повод обрезать или переписать данные. Единица интенсивности неизвестна. Изменение уровня широкого сигнала около 21–22° нельзя автоматически назвать количеством железа; локальная особенность около 33° сама по себе не устанавливает фазу. Контроль помогает задать вопросы о фоне матрицы, но прямое вычитание двух кривых независимых образцов без модели масштаба и неопределённости не создаёт «чистую» дифрактограмму фазы. Для оценки воспроизводимости при одинаковых номинальных условиях сравнивают независимые `3911` и `3913`; одинаковые точки угла внутри одной кривой не являются повторными образцами.

## 6. Кинетические и реологические кривые

Для подхода к плато $y(t)=y_\infty[1-\exp(-kt)]$ параметры описывают плато и скорость. Если начальное значение не равно нулю, используют обобщение с `y0`. Измерения должны захватывать информативную раннюю часть и область плато, иначе параметры плохо различимы. Пример оценки параметров приведён в [лекции 10](../modeling/10-scientific_and_stochastic_modeling.md).

Для степенной реологической модели $\tau=K\dot\gamma^n$, $\eta=K\dot\gamma^{n-1}$. При `n < 1` наблюдается разжижение при сдвиге, при `n > 1` — загущение; `n = 1` даёт постоянную вязкость в области применимости модели. Единицы `K` зависят от `n`.

Если `τ` выражено в Па, а скорость сдвига в с⁻¹, то `K` имеет единицу Па·сⁿ. Кажущаяся вязкость `η = τ/γ̇` вычисляется из тех же точек и не служит независимым подтверждением модели. Оценку `n` сопровождают указанным интервалом скоростей и графиком остатков; при смене интервала параметры могут измениться.

В измерении с возрастающей и убывающей скоростью сравнивают точки **одного запуска при одной скорости**, сохраняя направление, время и порядок. Различие ходов может зависеть от истории сдвига, времени на шаге и состояния образца; по одной петле нельзя установить механизм. [Учебный набор реальных кривых](data/rheology/README.md) содержит шесть отдельных образцов общей партии и два кодированных сеанса. Его можно использовать для описательной проверки модели, но точки одной кривой не являются независимыми приготовлениями.

Вот минимальный путь от широкого экспорта к сравнению направлений на одном образце. В первом отсчёте `R02` напряжение `0,5004 Па`, скорость `0,1 с⁻¹` и записанная вязкость `5,003 Па·с`; отношение `τ/γ̇≈5,004 Па·с`, разница обусловлена округлением исходных колонок. Сравнивать это отношение с `η` полезно для QC, но совпадение не является независимой проверкой физической модели.

```python
wide = pd.read_csv("experimental_analysis/data/rheology/viscosity_wide.csv")
prefix = "R02_"
names = ("point_id", "shear_rate_s_inv", "stress_Pa", "viscosity_Pa_s",
         "temperature_C", "elapsed_s", "segment_s")
run = wide[[prefix + name for name in names]].copy()
run.columns = names
parts = run["point_id"].str.split("|", n=1, expand=True, regex=False).astype(int)
run["sweep"] = parts[0].map({1: "up", 2: "down"})
run["point_no"] = parts[1]
assert len(run) == 200 and run.groupby("sweep").size().to_dict() == {
    "up": 100, "down": 100
}
assert not run.duplicated(["sweep", "point_no"]).any()
run["eta_from_stress_Pa_s"] = run["stress_Pa"] / run["shear_rate_s_inv"]

at_rate = run.loc[np.isclose(run["shear_rate_s_inv"], 101.1, atol=0.05)]
print(at_rate[["sweep", "point_no", "shear_rate_s_inv", "viscosity_Pa_s",
               "elapsed_s"]])
```

Две строки при близкой скорости принадлежат разным этапам **одного запуска**; перед вычитанием `η_down−η_up` проверяют точные скорости, время и порядок. Общая партия `B01` и сеанс `A` только у `R01` ограничивают сравнение составов. Нулевую последнюю точку `R01` сохраняют с отметкой QC и исключают **лишь из логарифмического фитирования**, поскольку логарифм нуля не существует; она остаётся в исходном файле и линейных рисунках. Степенной фит делают на объявленном диапазоне (например, `30–900 с⁻¹`), отдельно для направлений, показывая остатки в Па. Параметр `n` описывает эту серию и этот интервал; для эффекта рецептуры в новых партиях нужен новый план опыта.

В частотном эксперименте сравнивают модуль накопления G′ и потерь G″. Их пересечение меняет доминирующий отклик в измеренном диапазоне. До интерпретации проверяют линейную область деформации, инерцию и скольжение; пересечение само по себе не доказывает конкретный механизм.

## 7. Неопределённость и контроль серии

Учитывают повторяемость, калибровку, чувствительность к обработке и неопределённость аппроксимации. Суммирование дисперсий применимо к независимым компонентам с согласованными коэффициентами чувствительности. При зависимостях нужны ковариации; нельзя дважды учитывать один источник через разные названия.

Например, независимые относительные стандартные неопределённости `u_s/s=2%` (масштаб оси) и `u_A/A=3%` (прочие источники площади) дали бы для произведения `A·s` приблизительно `√(0,02²+0,03²)=3,6%`. Если `u_A` уже вычисляли в физических единицах с учётом `s`, прибавление 2% повторно ошибочно. Отдельный разброс признака от допустимых настроек фона и границ полосы — чувствительность к анализу; его нельзя просто объявить стандартной погрешностью без правила вероятностей для этих настроек.

Чувствительность изучают по допустимому диапазону фона, окна и границ интегрирования. Bootstrap выполняют на соответствующем независимом уровне; соседние точки спектра или технические повторы не всегда независимы.

Продолжение учебного примера создаёт серию в отдельном каталоге и журнал обработки:

```python
from pathlib import Path
import json

root = Path("spectra_demo")
raw_dir, out_dir = root / "raw", root / "processed"
raw_dir.mkdir(parents=True, exist_ok=True)
out_dir.mkdir(parents=True, exist_ok=True)
spectrum.to_csv(raw_dir / "sample_01.csv", index=False)
(out_dir / "parameters.json").write_text(
    json.dumps({"pipeline_version": "lecture08-v1", **params}, indent=2),
    encoding="utf-8",
)
rows = []
for file in sorted(raw_dir.glob("*.csv")):
    try:
        proc, peaks, band_area = process_curve(pd.read_csv(file))
        proc.to_csv(out_dir / file.name, index=False)
        peaks.to_csv(out_dir / f"{file.stem}_peaks.csv", index=False)
        rows.append({"file": file.name, "qc": "processed", "error": "",
                     "n_peaks": len(peaks), "area_480_560": band_area})
    except (ValueError, OSError, pd.errors.ParserError) as error:
        rows.append({"file": file.name, "qc": "failed", "error": str(error)})
pd.DataFrame(rows).to_csv(out_dir / "qc.csv", index=False)
```

`processed` означает успешное вычисление, не полную научную приёмку. В рабочем проекте добавляют ID образца и партии, версию калибровки и commit. Сдвиг стандарта, рост шума, необычное число пиков и параметры на границе требуют просмотра. Ошибка файла остаётся в журнале; неожиданные ошибки программирования не следует молча скрывать.
